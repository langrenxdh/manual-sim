# v1 之后的路线图

2026-10-03 · Donghui

> 中文版。英文版见 [`roadmap.en.md`](roadmap.en.md)。两个文件同步维护。

v1（M0–M3）已经完成，M4（分项练习与评分）已经做好。这份文档把下一步的所有想法都记下来（全部采纳），并定下实现顺序和每个里程碑的门槛。

**和设计文档的关系。** 这里是计划；规格仍然是 [`design.md`](design.md)。某个里程碑开始时，它的详细设计（参数、测试、决策）像 M0–M4 一样写进设计文档，这里只放链接。工作规则不变：一次只做一个里程碑，先进计划模式，到门槛就停。

## 顺序和理由

1. **先收尾 M4。** 它几乎完成了，而且后面的练习都建立在这套练习框架上。
2. **先做教练工具，再加练习（M5）。** 幽灵对比和进步曲线让*每一个*练习都更有用，包括之后新加的；而且只用到已经在记录的数据。
3. **不用转向的新练习（M6）** 复用直路、练习框架和评分，只需要小的增加：一辆前车、一段下坡、一个倒车起点。
4. **真实度（M7）放在练习之后**，因为离合温度和冷车会改变练习的手感和分数；在更真实的模型上只标定一次评分更好。其他车型放在这里，因为选车菜单建立在同样的按车调参上。
5. **考试模式和语音提示（M8）** 需要先有全套不用转向的练习可以选。
6. **转向（M9）放在大项目的最后，而不是最先。** 它是最大的改动：新的输入、横向物理模型、新的道路网络、不一样的力反馈设计。前面的每一项都能很快带来价值，等转向来了也不会白做。它先从一次短的硬件验证开始，就像 M0。
7. **分享（M10）** 要等产品完整之后才有意义，而且需要取消 docs/engineering-rules.en.md 硬规则 5（"硬件固定"）。到时候由我来决定；在那之前规则 5 不变。

### M5——教练 I：幽灵对比和进步曲线（想法 5、6）

**状态：已实现（2026-10-03），见设计文档 M5 决策记录；待手动检查。**

- **幽灵：** 每个练习保存最好一次完成尝试的遥测（`scores/ghosts/<练习>.bin`，和遥测同一格式）。回放时把它的踏板、转速、车速曲线淡淡地画在这次尝试后面，按尝试开始的时刻对齐。新的最好成绩会替换幽灵。
- **进步曲线：** 从菜单进入一个画面，用 `scores/scores.jsonl` 画出每个练习的分数随时间的变化，标出最好成绩和趋势，以及最常扣分的那一项。
- 不改物理。纯逻辑（对齐、趋势、"最常扣分项"）放在 `Sim.Training`，配测试。
- **门槛：** 一次没开好之后，幽灵能清楚看出和最好那次差在哪；进步曲线和我自己的感觉一致。

### M6——不用转向的更多练习（想法 1、2、3、4）

**状态：已实现（2026-10-03），见设计文档 M6 决策记录；待手动检查。**

- **红绿灯排队（1）：** 一辆按脚本走的前车（运动学，不走物理），按走走停停的节奏蠕行、停、走；队伍前头有一个红绿灯。按熄火、跟车太近或太远、离合发热、冲击评分。需要场景里加一辆前车和一个车距指标。
- **坡道连贯动作（2）：** 从平路出发，开到坡上，车头停在停车线前的一个范围里，再坡起。先按停车位置评分，再按现有的坡起评分。需要车头相对停车线的位置。
- **下坡和倒车上坡（3）：** 场景在坡顶平台之后加一段下坡。下坡练习：用合适的档位靠发动机制动守住限速，少用脚刹。倒车上坡：在坡底车头朝下，倒车往上开。需要扩展场景和一个倒车起点；物理本身已经支持倒档和负坡度。
- **补油降档（4）：** 三档约 50 km/h，降到二档；按冲击（离合接合时的峰值冲击）、离合发热和接合时转速是否对上评分。
- 新指标放在 `Sim.Training`，配脚本化测试（像 S1–S5）；场景改动在 `scene.json` 和 3D 画面里。
- **门槛：** 每个新练习都像真实场景，分数公平，标准和 M4 一样。

### M7——真实度和其他车型（想法 12、13、14）

**状态：已实现（2026-10-03），见设计文档 M7 决策记录；待手动检查。**

- **离合温度（12）：** 一个由打滑功率驱动（就是已经在算的打滑能量）、会散热的温度状态。离合过热时摩擦系数下降（衰减：容量变小、更容易打滑）；超过阈值时出现警告（"离合焦味"）。从物理中自然产生，不写特例（硬规则 2）。参数在车辆文件和调参面板里。
- **冷车和空调（13）：** 发动机温度状态；冷车时摩擦更大，ECU 的怠速目标更高，随着升温回到正常怠速（数值是估计，按自己的车凭脚感调）。空调作为一个可开关的怠速负载扭矩，由怠速控制器去补偿。
- **其他车型（14）：** 更多 `config/*.json` 车辆文件（例如一台小排量自吸汽油车、一台低转扭矩大的柴油车、一台重车）和选车菜单。没有真车数据，每台车按合理性和公开数据调。
- 物理改动放在 Sim.Core，配**新的验收测试 T6 起**（例如：高转速长时间打滑会让离合衰减；冷车怠速更高、升温后回落）。**T1–T5 必须保持通过。** 如果新效果和它们冲突，照例停下来讨论。
- 改完之后重新标定 M4、M6 的评分表，确认 S1–S5 仍然成立。
- **门槛：** 这些效果能感觉到但不夸张；Golf 仍然像 Golf；另一台车明显不同。

### M8——教练 II：考试模式和语音提示（想法 7、8）

**状态：已实现（2026-10-03），见设计文档 M8 决策记录；待手动检查。**

- **考试模式（7）：** 固定顺序的一组练习（例如：平路起步、坡道连贯动作、排队、降档、倒车上坡），每一项单独评分；每项都完成、总分达到门槛才算通过。结果记入历史。纯逻辑放在 `Sim.Training`，配测试。
- **语音提示（8）：** 只在教学模式下，由状态触发的简短语音或提示音：接近咬合点、怠速补偿快用完（"多给点油"）、开始溜车。用预录或合成的片段，通过 raylib 音频播放；触发规则是配置文件里的阈值。
- **门槛：** 考试像一次公平的测试；提示有帮助但不唠叨。

### M9——转向（v2 主打；想法 9、10、11）

**状态：已实现（2026-10-03），见设计文档 M9 决策记录；待手动检查。**

分成几步，每步都有自己的门槛：

- **M9a 硬件验证（像 M0）：** 以 1 kHz 读方向盘角度（axis 0 已经能读，全程约 1.2 万级）；验证 constant 力效果能以 100 Hz 以上更新，产生平顺、可变的回正力，不顿挫，同时叠加抖动正弦。`HwProbe` 加一个转向力测试。门槛：G29 上能得到平顺的可变力矩。
- **M9b 横向物理（Sim.Core；可以在云端做）：** 单轨（"自行车"）模型，加一个简单轮胎模型（抓地极限以内线性，之后饱和），横摆角速度、侧向加速度、转向比和回正力矩。新输入：方向盘角度。新的验收测试（例如：低速稳态转圈的半径和方向盘角度对得上；在合理的侧向 g 时达到抓地极限）。纵向模型和 T1–T5 不变。
- **M9c 道路：** 直路变成路网：弯道、一个丁字路口、一个环岛、一个停车场。用带曲率的中心线描述；3D 画面、相机转向和物理共用它。能检测开出路面（v2 不做碰撞物理）。
- **M9d 转向力反馈：** 方向盘力矩来自模型的回正力矩加一个回中弹簧，引擎抖动叠在上面；取代"弹簧默认关"。凭手感调。
- **M9e 转向练习：** 环岛（减速、二档、让行、边转边起步）、停车位、三点掉头；评分方式和其他练习一样，再加上是否压线。
- **门槛（M9 整体）：** 在 G29 上开过环岛和停车场感觉自然，v1 的纵向手感不变。

### M10——分享（想法 15；需要我决定取消硬规则 5）

- 安装包（自包含的 .NET 发布，首次运行时生成配置和首次设置）。
- 其他方向盘和踏板的输入设置向导：让用户逐个按下，自动识别轴和按钮（把 `HwProbe watch` 做成通用的），写出 `config/<设备>.json`；力反馈可选。
- 中英文界面：字符串表，带中文字形的字体。
- **门槛：** 朋友在自己的电脑和方向盘上安装后，不需要帮忙就能开起来。

## 每个里程碑都适用

- 双语文档和 docs/engineering-rules.en.md 的规则一直有效：不削弱测试，所有可调参数进配置文件和调参面板，物理永远不等待。
- 纯逻辑（Core、Training）可以在云端做；凡是要用 G29、屏幕或声音的必须在本地做（docs/engineering-rules.en.md）。
- 每个里程碑都以在 G29 上的手动检查结束，到门槛就停。
